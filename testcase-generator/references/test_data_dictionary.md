# 测试数据取值规范

本文件适用于所有游戏项目，不提供任何示例项目的固定数值。测试数据必须能够追溯到当前需求或当前项目资料。

## 取值优先级

按以下顺序取值，找到明确来源后停止：

1. 当前 PRD、原型、策划表或用户明确输入。
2. 当前项目的数据字典、配置表、接口契约或已确认设计稿。
3. 可读取的运行配置、服务端返回或测试环境真实数据。
4. 能由已知上下限推导的代表值，例如 `min`、`min-1`、`max`、`max+1`。
5. 仍无法确定时写 `待确认：具体数值/规则/终态`。

禁止沿用其他游戏、示例文档或历史项目中的关卡数、货币、道具、时间、尺寸、颜色、音效名、震动名及配置字段。

## 数据选择

| 场景 | 建议数据 |
|---|---|
| 正向流程 | 一个符合所有约束且容易核对的真实有效值 |
| 数值边界 | 已定义的 `min`、`max`，必要时补 `min-1`、`max+1` |
| 等价类 | 每个行为结果不同的有效/无效类别各取一个代表值 |
| 资源扣减 | 写明操作前余额、消耗量和操作后应得余额 |
| 概率或随机 | 使用可控种子、固定配置或足够样本；来源不明则待确认 |
| 网络与恢复 | 使用项目支持的网络/后台场景，不自行设定超时秒数 |
| 设备兼容 | 使用项目声明的最低、主流和高端设备范围 |
| 无独立输入 | 填 `-`，不得留空 |

## 记录要求

- 前置条件记录已有状态，测试数据记录本条实际输入，两者不要重复堆砌。
- 单位、精度、时区、平台、版本、环境等会影响判定时必须写明。
- 配置值或接口值应保留字段名；无法确认字段含义时不要猜测。
- 多组数据只有在相同前置下可连续执行且共享一个判定目标时才放进同一条用例，否则拆分。
- 推导边界值时写明依据；需求没有上下限时不得凭常识创造边界。
